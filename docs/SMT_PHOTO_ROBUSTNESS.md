# SMT 拍照谱鲁棒性试验

日期：2026-11-11。使用现有原生 GrandStaff 单系统 Q8 和扫描谱第一轮流程，测试本地 Oemer 示例中的真实拍照谱。**三组拍照场景均未得到可靠的整页结果，当前流程仍应限定为较平直的扫描谱。**

## 样本与范围

从本地 Oemer 仓库 docs/images 中裁出真实谱图区域，共四张图、三组场景：

- Wind：wind2_deskew.jpg 的左右两个版本，分别 1562×2353；两者源于同一场景，不能当作两个独立样本。这里不根据文件名断言哪边是未经处理的原照片。
- River Flows in You：river_1.jpg 左侧照片区域，2555×3508，有纸张弯曲、阴影、手写注释与高亮标记。
- 千与千寻：chihiro_3.jpg 左侧照片区域，3120×4160，有倾斜、阴影、注释和复杂和弦。

各照片目视均为五组钢琴上下谱表。River、千与千寻拼图右侧由 Oemer 重排生成的乐谱未参与测试，也未作为参考答案。来源是本地已有文件，未额外下载图片。[Oemer 项目](https://github.com/BreezeWhite/oemer)

本次没有逐音符转录这三组照片，**不提供照片音符 F1**。统计的是版面覆盖、原生输出是否合法、结构/时值/声部异常及整页流程能否可靠完成；不能与《稻香》扫描谱的逐音符 F1 混用。

## 原流程的实际表现

所有原生推理均为相同的 CrispEmbed v0.17.18 CPU、GrandStaff 单系统 Q8、4 线程，每条异常行最多三次额外重试。未更换权重，没有加入照片矫正。

- **Wind 左侧版本**：实际五行，只切出了两行；遗漏了页面的大部分内容。输出两行全部有未解决异常，约 **50.3 秒**。命令没有因为这些非致命异常报错，但 report 中两行均标为 unresolved，不能视为成功。
- **Wind 右侧版本**：能切出五行，但 **5/5 行均有未解决异常**。第一行全部候选无法通过解析，选中的输出包含不合法的声部合并；其他行还有小节数量、时值、延音或拍长无法验证的问题。约 **103.6 秒**后整页以失败结束。
- **River 照片**：实际五行，只切出了两行；两行均有未解决异常。约 **15.6 秒**，同样存在“只处理部分页面”的风险。
- **千与千寻照片**：无法可靠配对上下谱表，在布局阶段拒绝，未启动模型推理，约 **0.7 秒**。

这说明只做扫描谱的尺寸归一化和局部重试，不能解决照片的几何畸变与识别域差异。多次重试增加耗时，也可能仍得不到有效结果。这里的异常分不是音符准确率；照片上从图像竖线推导的小节数量也可能不可靠。

## 测试发现并修复的漏切风险

原检测器只检查已找到的全局谱线能否配成对，无法证明页面其他位置没有漏掉谱表。Wind 左侧、River 因弯曲/倾斜使部分谱线无法形成全宽水平投影，因而只剩两行却仍通过布局检查。

现已增加 **四个局部纵向切片的覆盖复查**：

1. 在页面宽度 20%、40%、60%、80% 位置取窄区域，独立寻找局部五线谱。
2. 只保留间距与全局谱表相近、有完整五线支持的局部候选。
3. 如果同一未覆盖区域在至少两个切片中有支持，拒绝当前布局，提示需要矫正或检查，避免返回漏掉大部分页面的结果。

这是一项保守的完整性检查，不会自动拉直、补画谱线，也不保证能发现所有漏切。实现位于 [布局检测](../tools/ocr/smt_scan_layout.py)。

加入检查后：

- Wind 左侧发现四条有多切片支持的未覆盖谱表轨迹，布局阶段拒绝。
- River 发现两条有多切片支持的未覆盖轨迹，布局阶段拒绝。
- 千与千寻仍因无法配对拒绝。
- 三份拒绝均实测保存了 layout_rejected 状态和源图哈希，未启动识别进程，约 0.5～0.7 秒。
- Wind 右侧仍可通过布局复查，但模型/符号解析方面的问题仍存在。新增检查没有改变它的五张模型输入图像，故沿用已完成的原生推理诊断，未再重复运行二十次推理。

流水线也补充了明确的 report 状态：layout_rejected、recognition_failed、needs_review、no_rule_anomaly。no_rule_anomaly 仅表示未发现规则异常，不代表音符全部正确。

## 受控倾斜测试

另对《稻香》清晰扫描图进行旋转，仅测试布局阶段，不与真实照片混算：

- 旋转 **0.25°**：仍可检测五组谱表。
- 旋转 **0.5°、1°、2°**：当前布局检测均拒绝。

这些是该尺寸、该字体图片的单次结果，不是通用的倾斜容忍阈值。它表明即使简单倾斜也可能需要预先校正；通过布局的 0.25° 图片未再跑模型，不能据此宣称其音符准确度不变。

## 扫描谱回归与证据

新增一个“局部能看到、全局水平投影漏掉倾斜谱行”的回归测试，当前 **18 项测试全部通过**。

两张《稻香》扫描谱在新检测器下仍各有五行，十张模型输入文件均与第一轮优化时逐字节一致。没有为照片修改正常扫描谱的裁剪或候选选择规则，也没有重跑相同的扫描谱模型推理来重复计量准确度。

本地证据位于 publish/smt-experiment/photo-robustness：

- cases.json：源文件 SHA-256、裁剪坐标、裁片 SHA-256、场景分组、目视行数。
- baseline-summary.json 和 baseline-*/：原流程完整运行结果、所有候选、stdout/stderr、耗时和异常诊断。
- recognition-diagnostics.json：每行候选的原生退出码、解析错误和选择结果。
- audited-layout-summary.json：加入覆盖检查后的四份照片及两份扫描图的布局结果。
- audited-wind-left、audited-river-photo、audited-chihiro-photo：真实流水线在模型启动前拒绝的 report.json。
- post-guard-integration.json：拒绝状态及耗时。
- synthetic-stress.json：单独记录受控旋转的布局结果。

可使用现有开发环境复跑任意裁片，输出目录必须全新：

```powershell
python tools/ocr/optimize_smt_scan.py `

```

## 判断

简单的整图旋转校正相对容易，但本次照片还存在透视、非均匀纸张弯曲、阴影和遮挡。稳定处理需要局部谱线跟踪、几何重建及足够多样的验证样本；图像矫正后，符号识别也不保证达到扫描谱水平。为当前项目投入完整照片适配的收益不足。

**范围决定（2026-11-11）：按用户“若不好做则放弃”的要求，放弃 SMT 拍照谱适配及自动照片矫正，继续完善清晰、平直扫描谱和电子谱截图。** 不再将照片权重、透视矫正或曲面展平列为接入前置任务。

保留本次照片测试及局部覆盖保护，用于防止漏切后返回不完整结果。失败提示已明确要求清晰平直的输入，不再提示必须开发自动矫正。输入按实际几何质量检查，不依据 JPG/PNG 扩展名或拍摄设备硬性拦截，平直的 JPG 扫描件仍可使用。此决定限定于本轮 SMT 五线谱路线，不修改既有简谱识别或 Oemer 的实现。
