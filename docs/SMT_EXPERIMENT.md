# SMT 原生推理与扫描谱试验

日期：2026-11-11。当前适配清晰、平直的扫描谱和电子谱截图；照片鲁棒性试验后，按用户要求放弃拍照谱适配及自动照片矫正。本轮完成独立试验工具与真实样本验证，尚未接入应用的 OCR 导入流程。

后续已完成与当前附加包 Oemer 的同图对照，并逐图转录全部 17 小节、243 个发声音符作为参考：SMT 清晰图完整音符 F1 为 98.97%，模糊图为 96.52%，拍号和休止另有错误。详细评分范围、Oemer 结果与限制见 [扫描谱准确度对照](OCR_SMT_OEMER_COMPARISON.md)。下文保留最初部署与预处理试验的记录。

第一轮稳健切行、异常校验和局部重识别现已完成，两图 F1 分别提高到 99.18% 和 98.57%，含重试耗时约 27、33 秒，见 [优化与测试记录](SMT_SCAN_OPTIMIZATION.md)。

## 当前结果

Windows x64 CPU 原生推理已跑通，识别进程不需要 Python。扫描谱采用“检测水平五线谱 → 配对上下谱表 → 逐行裁剪 → 统一谱线间距 → 抑制浅色水印 → 逐行 SMT”后，小节数量比直接按谱行高度缩放更稳定。

但这组原生 Q8 权重尚不能直接替换 Oemer：清晰扫描谱首行仍有拍号、全小节休止识别错误；末行存在全空记录。无结构错误、退出码为 0 或小节数量一致，都不能证明音高、时值和声部正确。

结果保留在本地忽略目录 `publish/smt-experiment/`，包含原图、处理图、原始符号、标准化符号、stderr、文件哈希和耗时。图片和模型未加入 Git。

## 扫描谱对照

用户提供的两张《稻香》内容相同，均有五组钢琴双谱表，逐行 3、3、4、4、3 小节，合计 17 小节。

- 清晰图：`inputs/0011877-w-b-1.png`，2500×3400，SHA-256 `dbfb462d9b433e21a05fa84d2788015ed84d48798d95c35038cb0abc8fc4f152`。
- 模糊图：`inputs/clipboard_20261111_105629.png`，474×644，SHA-256 `f273bd6a77e1ceea7e3ca5837f4b844327642dc51616fbeb2bdaee15145473c4`。主要差异是分辨率，不能把放大等同于恢复细节。

所有成功试验固定 CPU、4 线程，每次新建识别进程，顺序执行。以下为单次进程耗时；不包含裁剪、解压、SHA 校验、输出分析，也没有重复测量或冷缓存控制。

### 整页模型

- 两张图都保留整页边距、等比调整到高 1485 像素。清晰图 27.714 秒，模糊图 25.743 秒。
- 输出分别有 16 和 18 条小节线记录，二者不一致；两份输出虽通过本工具的基础结构检查，但仍有可见节奏、音高和覆盖问题。整页输出未必包含起始小节线，不能简单把记录条数视为小节数。
- 清晰原图直接输入曾运行 128.625 秒仍无输出，人工终止，退出码 -1。该记录不是成功样本，也不是自动超时；`metrics.json` 中 `timedOut=false`。高分辨率原图不适合直接交给本次原生实现，后续必须限制输入尺寸。

### 单系统模型：按整行高度缩放的基线

- 自动切出每图五行，分别等比调整到高 256 像素。
- 清晰图五行合计 20.857 秒；模糊图合计 17.768 秒。
- 扣除每行起始小节线后，输出小节数量分别为 21、18，与原图 17 不符。
- 两张首行均错误输出 `*M2/4`，原图为 4/4。清晰图有三行出现全空记录等基础结构问题。

### 单系统模型：谱线间距与水印预处理

- 用检测到的谱线间距缩放到 8 像素，保持长宽比，并在底部补白至至少 256 像素高。
- 裁剪后、缩放前，将亮度大于 210 的像素置白，降低浅色水印影响。此阈值是本次对照参数，不能假定适合所有低对比度扫描件。
- 清晰图五行合计 **14.891 秒**；模糊图合计 **16.103 秒**。
- 两份输出的逐行小节数量均为 **3、3、4、4、3**，与原图一致。这只是数量核对，尚未逐音符校验 17 小节。
- 清晰图首行输出 `*M3/4`，低音全小节休止输出 `2.r`，均有错误。模糊图同处输出 `*M4/4` 和 `1r`，这两处与原图一致。
- 清晰图末行有 4 条全空记录；模糊图第三行有 1 条、末行有 3 条。全空记录本身不提供新的演奏事件，但不能用“删掉空记录”代替节奏、覆盖和声部校验。
- 清晰图首行还比较了 8/10 像素谱线间距、有/无水印抑制四种组合。8 像素且抑制水印的输出结构更稳定，但仍未修正清晰图拍号；并非已经通过准确率验收的最优参数。

原始记录位于 `results/scan-*/`，汇总在 `results/scan-summary.json`。每行输出为独立乐谱片段，尚未合并上下谱表、延音和跨行声部。

## 运行链路的标准样本检查

另使用 [PRAIG/grandstaff](https://huggingface.co/datasets/PRAIG/grandstaff) 的 `test[0]`，672×256。原始数据行保存在 `sample-row.json`，标注在 `inputs/grandstaff-test-0.reference.krn`。

- 单系统 Q8 首次 3.156 秒，可复跑脚本验证 3.883 秒。
- 标注与输出均有 47 个音高符号、1 个休止符号；标准化后 352 字符中相差 1 字符：`16bn` 输出为 `16b`。
- 这表明原生链路至少能处理一张同域标准样本，不代表扫描谱准确率；字符编辑差异也不是音符或节奏准确率。未对整套测试集做评估。

## 复跑方法

PowerShell 7；三个下载文件放在 `publish/smt-experiment/` 根目录。`Test-Smt.ps1` 只使用已校验的 CPU 包和选定模型，不使用同名残缺下载。每次指定新的输出目录。

```powershell
# 先准备扫描谱。Python 仅供开发期图像处理，需 Pillow、NumPy。
# 不传两个可选参数时，可复现“整行高 256”基线。
python tools/ocr/research/prepare_smt_scan.py `
  publish/smt-experiment/inputs/0011877-w-b-1.png `
  publish/smt-experiment/inputs/scan-clear-replay `
  --staff-spacing 8 --suppress-faint

# 一次识别一个上下谱表系统。
pwsh -File tools/ocr/research/Test-Smt.ps1 `
  -ImagePath publish/smt-experiment/inputs/scan-clear-replay/system-01.png `
  -Model System

# 整页模型使用准备脚本另行生成的、未经水印抑制的整页缩放图。
pwsh -File tools/ocr/research/Test-Smt.ps1 `
  -ImagePath publish/smt-experiment/inputs/scan-clear-replay/page-1485.png `
  -Model Page

# 分析打印出的本次结果目录。仅分析结构、计数和可选的标注字符差异。
python tools/ocr/research/analyze_smt_output.py <结果目录>/recognized.tokens.txt
```

`prepare_smt_scan.py` 当前只支持近水平、单钢琴、成对五线谱的扫描页。它使用水平投影、五条等间距谱线校验和上下谱表配对；无法可靠检测时失败，不静默生成空结果。不支持照片矫正、多乐器编制和通用版面分析。输出包含源图哈希、裁剪坐标、谱线位置和处理尺寸，保留原图。

`Test-Smt.ps1` 隐藏启动窗口，同时读取 stdout/stderr，固定 CPU，记录输入/模型哈希与耗时。默认单次 180 秒，超时终止进程树并保留证据。已验证含空格路径、成功输出、1 秒超时清理；图像准备已验证两张图各五行、处理像素可复现、拒绝空白页和覆盖已有输出目录。分析工具已检查字符序列还原、和弦空格、空结果和全空记录等情况。

## 继续接入的条件

1. 先对齐官方与原生推理的输入预处理，在同一条清晰谱行核查拍号、全小节休止、附点和延音，区分模型错误与移植差异。
2. 人工标注这张谱的音高、起点、时值、声部，再增加其他字体和不同密度的扫描谱；两张同内容图片不足以确定通用参数。
3. 质量达到要求后，再实现 ekern/beKern 到内部曲谱的转换、跨行拼接、取消与进度，以及附加包发布。当前应用继续使用既有后端，内存管理与拍照适配不在本轮范围内。
